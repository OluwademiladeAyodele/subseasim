# Surrogate models

Code: `backend/app/surrogates/` (`gp.py`, `model.py`, `doe.py`), job kind
`surrogate_build`. UI: the **Surrogate models** page.

**Model status: surrogate-model prediction.** A surrogate reproduces its
training source quickly, inside the range it was trained on. It is never
more accurate than that source, and it is labelled with what it was trained
on. For example: "Surrogate-model prediction - trained on simulator data
(SubseaSim steady twins), not CFD or field data".

## Architecture

| Layer | Source | In SubseaSim |
|---|---|---|
| High-fidelity cases | CFD, experiments, vendor data, field data | **Imported only.** SubseaSim never generates or ships such data |
| Simulator cases | Steady twins of a session (same models as the live session) | Generated by a Latin-hypercube design (background job) |
| Case library | The cases a surrogate is trained on, each tagged with `source` and `reference` | Stored with the surrogate |
| Surrogate | Gaussian process or quadratic response surface | Trained, cross-validated, stored |
| Prediction | Mean and 95 % interval, plus an envelope check | Near-instant |
| Fall-back | High-fidelity calculation when outside the envelope | "Check with the simulator" (steady twin); external CFD remains with the user |

### Inputs and outputs

**Inputs:**

- choke opening;
- reservoir and manifold pressure;
- water cut;
- GOR;
- sand rate (imposed, measured);
- D50.

These are the same changes as a scenario-comparison case.

**Outputs:**

- oil, gas and water rates;
- choke ΔP;
- drawdown;
- sanding risk index;
- sand at the choke;
- choke jet velocity;
- cage-hole wear rate.

### Simulator design

- `scipy.stats.qmc.LatinHypercube` with a fixed seed, so it is
  reproducible.
- 8 to 200 cases, each solved on a steady twin carrying the session state.
- The choke opening actually applied, on the actuator's step grid, is used as
  the training input.
- About 1 s per case, run as a background job.

### Methods

**Gaussian process** (`gp.py`, numpy / scipy; Rasmussen & Williams 2006):

- squared-exponential ARD kernel plus white noise, on inputs scaled to
  [0, 1] and standardised outputs;
- hyper-parameters maximise the log marginal likelihood (L-BFGS-B, several
  starts);
- the predictive standard deviation gives the 95 % interval.

**Quadratic response surface:** full quadratic least squares with a light
ridge. The standard deviation comes from the residual variance and the
leverage. It needs at least 1 + d + d(d+1)/2 + 3 cases.

### Validation (always shown)

Leave-one-out cross-validation for each output:

- **GP:** closed form, R&W eq. 5.12, checked against brute-force refits in
  the tests.
- **Quadratic surface:** PRESS residuals.

Reported: RMSE, R², and the **coverage of the 95 % interval** (the share of
left-out cases inside it). A parity plot is shown for each output.

Coverage well below 95 % means the interval is over-confident. This
typically happens for outputs with a step, such as sand at the choke at the
sanding onset (risk index 1). The page highlights such outputs.

### Operating envelope

Every prediction checks two things:

1. **Training range.** Every input lies inside its training range.
2. **Sparse region.** The distance to the nearest training case (scaled
   inputs) is not larger than the largest nearest-neighbour gap of the
   training design. Otherwise the point lies in a void of the design.

Outside the envelope, the prediction is flagged: "the surrogate is not
validated here; run a high-fidelity calculation". The page offers **Check
with the simulator**, which solves the point on a steady twin and compares
it with the surrogate, including whether the simulator value is inside the
95 % interval.

### Imported cases

`POST /api/surrogates/import` takes:

- a CSV with the chosen input and output columns, plus `source`
  (simulator / cfd / experiment / vendor / field) and an optional
  `reference`;
- `name`, `method`, `inputs` and `outputs`.

The import is atomic: any bad line rejects the file, with the line number.
The surrogate status then reads, for example, "trained on imported cfd data".

**Storage.** Surrogates are stored in the records database (schema 3, table
`surrogates`) as their case library and settings. Fitting is deterministic,
so a loaded surrogate reproduces the saved one exactly.

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/sessions/{sid}/jobs` `{kind: "surrogate_build", params: {name, method, bounds: {input: [min, max]}, outputs, n_samples}}` | Train on simulator cases (202) |
| POST | `/api/surrogates/import` | Train on imported cases (201) |
| GET | `/api/surrogates`, `/api/surrogates/{id}` | List; model card (inputs and envelope, outputs, sources, status, validation, limitations) |
| POST | `/api/surrogates/{id}/predict` `{inputs}` | Prediction with interval, envelope, status |
| POST | `/api/sessions/{sid}/surrogates/{id}/check` `{inputs}` | Simulator check of one point |
| DELETE | `/api/surrogates/{id}` | Delete |

## Limitations

- **Valid only inside the training envelope.**
- **No added accuracy.** A surrogate of the simulator inherits every
  simulator limitation and is not more accurate than the simulator.
- **Cross-validation scope.** It measures fidelity to the training source,
  not the accuracy of that source.
- **Step changes are smoothed.** Examples are the sanding onset and changes
  of flow regime; check their coverage.
- **No CFD is bundled.** The architecture accepts CFD, experiment and vendor
  cases, but SubseaSim contains none. Predictions labelled "simulator" are
  not CFD results.

## Verification

`backend/tests/test_surrogates.py` checks:

- GP accuracy on a known function;
- the closed-form leave-one-out equals brute-force refits;
- uncertainty grows away from the data;
- the quadratic surface is exact on a quadratic;
- validation results, the envelope (range and void) and status labels;
- data checks: too few cases, an unknown source, incomplete cases;
- the storage round trip reproduces predictions;
- CSV import validation;
- Latin-hypercube stratification;
- a simulator-trained surrogate matches the simulator at a new point within
  2 %;
- the full API.

`frontend/src/surrogates.test.tsx` uses a real backend-trained surrogate,
and the end-to-end test trains, predicts and checks.
